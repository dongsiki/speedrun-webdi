## 브라우저 검사

Headless Chrome·Playwright, 800×600, 소프트웨어 WebGL 환경에서 수행했습니다.

- 실제용: 기존 AI 관문을 버튼·길게 누르기로 통과하여 땅파기 진입.
- 실제용: 전구·미로·기억·마지막 걸음·실 꿰기·짐 싸기·MRI의 화면 생성과 로비 복귀.
- 미로: 포인터락 획득, 자동 마우스 이동 이벤트와 W 키 전달.
- 전구: 스위치 버튼 15개 이상 생성.
- 기존 localStorage 기록의 새로고침 후 유지.
- 개발자용: 메뉴 9개 항목(게임 7개·춤·클리어 화면)의 진입과 메뉴 복귀.
- `file://`: 실제용 AI 관문→로비, 개발자용 전구 진입·메뉴 복귀.
- 위 완료된 경로에서 JavaScript 런타임 오류 없음.

검사 초기에 테스트 서버 접속 제한, 전구 화면을 canvas로 가정한 선택자, 개발자용 메시지 채널 오기가 있었습니다. 접속 권한으로 재시도하고 **검사 코드만** 바로잡았습니다. 실행용 게임 코드는 바뀌지 않았습니다.

## 검증 범위

게임의 `complete`·`fail`·`back`·`menu` 메시지를 검사에서 보내 연결 경로를 확인했습니다. 모든 퍼즐을 사람이 실제로 풀어 완주했다는 뜻은 아닙니다. 실제용과 개발자용의 차이, 미로 입력 코드, 기존 모든 콘텐츠 보존은 실행본 전체 해시 일치로 함께 확인했습니다.

실제 손으로 마우스를 움직였을 때의 체감, 스피커 청취, 물리 USB·다른 PC 하드웨어 시험은 수행하지 않았습니다. 모바일 전용 조작은 추가하지 않았습니다. 게시 이후 원격 확인은 배포 작업 결과에서 별도로 보고합니다.

```sh
npm run build
npm run test:baseline
# Playwright가 준비된 환경에서 선택 실행
node scripts/browser-check.cjs
node scripts/browser-check.cjs --base-url https://dongsiki.github.io/speedrun-webdi/
```
